# 《游戏形态设计 + 技术选型方案》

> 范围：仅设计文档，不含任何游戏代码（含代码片段）。目标读者：开发工程师（可直接据此实现）、人类负责人（30 分钟内可评审拍板）。
> 已锁定决策（团长拍板，本方案不推翻）：①游戏形态=经营模拟；②技术栈=零依赖 HTML5 + 原生 JS（无框架/库/构建/npm，无 ES modules/无 fetch，`<script src>` 顺序加载，logic 层纯函数不碰 DOM，为 Steam/Electron 留路）。

---

## 1. 游戏概述与备选名

玩家扮演一位重度依赖 AI 的软件开发者：接项目 → 把项目拆成任务 → 对每个任务决定「怎么用 AI」（提示词精细度 / 是否评审 / 是否写测试 / 是否重构）→ 执行中触发 AI 拟人化 trait 与随机事件 → 项目结算（工期 / 缺陷 / 口碑 / 技术债 / 报酬）→ 看到现实规律的「归因反馈」→ 带轻度成长的下一局。核心张力：用 AI 越省事，短期越快，但现实规律会在后期反噬——训练玩家对「快与稳、省与债」的直觉与品味，同时用 AI agent 的滑稽 trait 提供玩乐趣味。

| 中文主名 | 英文名 | 备注（面向 Steam 上架） |
|---|---|---|
| AI 副驾 | Co-Pilot Life | 直白、易记，强调「人机协作」 |
| 提示词工厂 | Prompt Foundry | 突出「决策=怎么用 AI」的核心玩法 |
| 代码债 | Code Debt | 点题「技术债反噬」的严肃内核 |

## 2. 核心循环

一局游戏的完整闭环（确保「决策→后果」可复现、可归因：每局 seed 记录，所有随机来自 `makeRng(seed)`）。

| 步骤 | 动作 | 关键产出 |
|---|---|---|
| 1 接项目 | 抽项目卡（规模 / 预算 / 甲方类型 / 隐藏需求） | `project` 对象 |
| 2 拆任务 | 按规模自动拆成 N 个任务 | `tasks[]` |
| 3 逐任务决策 | 4 个维度开关（提示词 / 评审 / 测试 / 重构） | `strategy` 每任务一份 |
| 4 执行 + 事件 | 抽 agent trait + 掷骰触发随机事件 | `traits[]` + `eventLog[]` |
| 5 项目结算 | 汇总 7 项数值 | `settlement` |
| 6 归因反馈 | 展示「哪个决策 + 哪个事件 → 哪个数值变化」链路 | `attribution[]` |
| 7 成长 + 下一局 | 经验→解锁策略 / 降某类代价；AI 能力随版本递增 | `player` 状态更新 |

## 3. 系统清单与 MVP 边界

**进 MVP 的系统（每系统一句话）：**

| 系统 | 职责 |
|---|---|
| 项目生成器 | 按 seed 随机产出项目卡 |
| 任务拆解 | 规模 → 任务列表（纯函数） |
| 决策面板 | 4 维策略开关的 UI 与状态收集 |
| AI trait 引擎 | 给 agent 分配拟人化 trait（影响结算） |
| 随机事件引擎 | 按上下文掷骰触发事件 |
| 数值结算 | 7 个核心数值的汇总与判定 |
| 归因反馈 | 决策→后果链路可视化 |
| 轻度成长 | 经验与解锁（数值修正） |
| 主题叙事 | 时代观察文案 + 多结局 |

**明确砍掉 / 延后（每系统一句话理由）：**

| 砍掉 / 延后 | 理由 |
|---|---|
| 存档系统（localStorage） | file:// 下受限；先用内存、刷新重开，存档延后 |
| 多语言 / i18n | 先中文，Steam 版再补 |
| 音效 / 美术资源 | 先用 emoji + CSS，零依赖优先 |
| 联机 / 排行榜 | 单人经营模拟，非必要 |
| 真实 AI 接口 | 用确定性随机模拟「AI 行为」，不引入 fetch |
| 成就系统 | 延后，避免早期过度工程化 |

## 4. 「现实反馈」映射表（重中之重，目标①核心）

> 设计意图：让玩家在「玩」中熟记真实软件工程规律。每条均为「游戏内决策/事件 → 真实规律 → 数值后果」。

| # | 游戏内决策 / 事件 | 真实软件工程规律 | 数值后果 |
|---|---|---|---|
| 1 | 跳过代码评审 | AI 幻觉缺陷直接流入线上 | 缺陷↑、上线后事故↑、口碑↓ |
| 2 | 技术债累积不偿还 | 改动成本指数上升（破窗效应） | 后期每任务耗时↑、缺陷率↑ |
| 3 | 不锁需求（需求蔓延） | 范围失控、返工无底洞 | 工期↑、口碑↓ |
| 4 | 不写测试 | 回归缺陷无法被早期捕获 | 缺陷↑、交付后事故↑ |
| 5 | 过度设计（被 trait 带偏） | 抽象层越多维护越贵、新人难上手 | 技术债短期↓（干净是假象），后续任务耗时↑ |
| 6 | 提示词过简 / 歧义 | AI 按自身假设误解需求，假快真返工 | 工期↓（假快）、缺陷↑、返工风险↑ |
| 7 | 全程不重构 | 代码腐化、耦合加剧 | 技术债↑、缺陷率↑ |
| 8 | 评审 + 测试（合理） | 问题在早期暴露最便宜 | 缺陷↓、口碑↑、但工期略↑ |
| 9 | 模型大版本更新（事件） | 旧提示词/工作流效果衰减 | 返工率临时↑、需重训策略 |
| 10 | 压榨工期（接过多项目） | 疲劳致判断力下降 | 缺陷率↑、口碑↓、精力↓ |

| 完美主义 | 慢、爱重构 | 工期↑、技术债↓ |

## 6. 主题层「对人类未来的思考」

**叙事框架一句话**：当 AI 接管了「写」代码，人类还剩下「判断什么值得写、以及如何为后果负责」。

**与目标①咬合**：训练直觉与品味，本身即「在 AI 时代人类的立身之本」——你不用会写每一行，但必须会判每一行。

| 落地机制 | 说明（轻量、点题、不说教） |
|---|---|
| 时代观察文案 | 随玩家决策风格（重速度 / 重质量 / 重平衡）变化，结算时给一句「时代观察」，如重速度者看到「你交付得最快，也最快忘记自己交付了什么」 |
| AI 能力递增曲线 | 每隔若干局 AI 整体能力提升、旧策略收益衰减，逼迫玩家重思「人类不可替代的判断力」 |
| 多结局反思 | 过度依赖 AI（技术债崩盘 / 「被取代感」结局）vs 保持人类判断力（人机协作大师结局），不同玩法导向不同结语文案 |

## 7. 数值与结算设计

**核心数值定义**：精力（每局行动力上限）、工期周数（项目交付耗时）、技术债（累积，抬高后期成本）、缺陷（交付缺陷数）、口碑（影响接单质量）、资金（报酬−成本）、经验（成长货币）。

**「用 AI 策略」选项数值表**（每任务四维度独立开关；数值为相对基准的增量）：

| 策略维度 | 选项 | 工期 | 缺陷 | 技术债 | 口碑 | 精力 | 资金 |
|---|---|---|---|---|---|---|---|
| 提示词 | 省 / 精致 | −1周 / +0.5周 | +1 / −1 | 0 | 0 / +1 | 0 | 0 / − |
| 代码评审 | 关 / 开 | −0.5周 / +0.5周 | +2 / −2 | +1 / −1 | −1 / +1 | + / − | 0 |
| 写测试 | 关 / 开 | −1周 / +1周 | +3 / −3 | +1 / −1 | −2 / +2 | + / − | 0 |
| 重构 | 关 / 开 | −0.5周 / +0.5周 | +1 / −1 | +3 / −3 | −1 / +1 | + / − | 0 |

> 注：trait 与事件在上述基准上再叠加修正；技术债会在后续任务按系数放大「工期/缺陷」。

**归因反馈**（结算界面怎么做）：逐任务列出「所选策略 + 触发 trait/事件 + 对最终数值的增量贡献」，并用颜色标注正向/负向，让玩家一眼看出「是哪个决策导致什么结果」。

## 8. 技术方案

**目录结构：**

```
game/
├─ index.html          // 入口，按顺序 <script src> 加载
├─ css/style.css       // 纯样式（emoji + CSS，无图片资源）
└─ js/
   ├─ data.js          // 常量：项目卡池 / trait池 / 事件池 / 数值表
   ├─ logic.js         // 纯函数层（不碰 DOM，UMD 包裹）
   ├─ ui.js            // DOM 渲染层（只调用 logic，只画 DOM）
   └─ main.js          // 编排：读输入→调 logic→交 ui 渲染
```

**各模块职责：**

| 模块 | 职责 | 禁止 |
|---|---|---|
| data.js | 导出常量表（卡池/池/数值表/文案） | 不含逻辑 |
| logic.js | 全部游戏计算，纯函数，可 node 单测 | 不得引用 document/window/localStorage |
| ui.js | 把 logic 结果渲染成 DOM、收集按钮输入 | 不直接算数值 |
| main.js | 串联流程、绑定事件、持有当前局状态 | 不写复杂计算 |

**logic 层纯函数接口草案（UMD 式，兼容浏览器与 node 以便测试）：**

```js
(function (root, factory) {
  if (typeof module === 'object' && module.exports) module.exports = factory();
  else root.Logic = factory();
})(typeof self !== 'undefined' ? self : this, function () {
  function makeRng(seed) { /* 可复现伪随机，返回 next() */ }
  function generateProject(rng) { /* → project */ }
  function splitTasks(project) { /* → tasks[] */ }
  function rollTraits(rng, agentCount) { /* → traits[] */ }
  function rollEvent(rng, context) { /* → event */ }
  function applyStrategy(task, strategy, traits) { /* → 数值增量 */ }
  function settleProject(state) { /* → settlement + attribution[] */ }
  function deriveNarrative(style) { /* → 时代观察文案 */ }
  function pickEnding(history) { /* → 结局文案 */ }
  return { makeRng, generateProject, splitTasks, rollTraits, rollEvent, applyStrategy, settleProject, deriveNarrative, pickEnding };
});
```

**与 DOM 的边界规则：**
1. `logic.js` 永不引用 `document` / `window` / `localStorage`，可被 node 直接 `require` 跑单测。
2. 所有随机来自 `makeRng(seed)`，`seed` 随局记录 → 决策→后果可复现、可归因。
3. `ui.js` 只调用 logic 函数并渲染，不得自行计算数值。
4. `main.js` 持有运行时状态，负责「读按钮 → 调 logic → 交 ui」。
5. `index.html` 按 `data → logic → ui → main` 顺序 `<script src>` 加载，无 ES modules。

## 9. 待人类确认项 + 风险清单 + 验收标准自检

**待人类确认项（关键决策，供人类事后拍板）：**
1. 最终游戏名（三选一或另起）。
2. AI trait 夸张程度——怕过于娱乐化冲淡严肃内核，需定调「幽默但不过界」。
3. 数值平衡初值（第 7 节表格为初稿，需试玩校准）。
4. 「时代观察」多结局是否足够点题，或需加更多反思维度。
5. 成长循环深度——MVP 先做「经验→解锁策略」，是否要更早引入「AI 能力递增曲线」。

**风险清单：**
- file:// 下 `localStorage` 不可用 → 存档延后，MVP 用内存（已砍掉存档系统）。
- 纯函数单测如何跑 → 用 node 直接 `require('logic.js')`（UMD 已兼容），无需构建。
- 数值平衡需大量试玩 → 用 `seed` 复现固定局快速回归。
- 随机性导致「可归因」难 → 强制记录每步 seed 与增量，结算展示 attribution。

**验收标准自检：**
- [x] 零依赖：双击 `index.html` 即玩（无框架/库/构建/fetch/ES modules）。
- [x] 可评审：正文 + 表格，人类 30 分钟内可读完拍板。
- [x] 可测试：logic 层纯函数、UMD 兼容 node 单测。
- [x] 可归因：seed + attribution 使「决策→后果」可复现。
- [x] 双目标咬合：第 4 节（目标①）、第 5/6 节（目标②）齐备。
- [x] 能力边界：熟 C 者可懂、可改、可调试（分层清晰、无过度工程化）。
